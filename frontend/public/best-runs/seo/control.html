Pages found: 9 HTML pages that return 200, 1 URL in the sitemap that returns 404, 2 broken URLs linked from pages (`/zh/`, `/teas/dragon-well/`), and a 2-step redirect chain (`/shop/` → `/store/` → `/teas/`).

## Details

### High

**1. Best-selling product is noindexed: http://lumentea.test/teas/jasmine-silver-needle/**
The `<head>` contains `<meta name="robots" content="noindex, follow">`. The homepage calls this the best seller, yet it will be dropped from search results. The page also declares a self-referencing canonical, which sends the opposite signal.
Fix: remove the noindex.

**2. Product page noindexed by an HTTP header: http://lumentea.test/teas/bai-mudan/**
The response includes `X-Robots-Tag: noindex`. It is easy to miss because the HTML looks fine. With #1, neither of the two products the shop sells can appear in search results.
Fix: remove the header from the server config.

**3. robots.txt blocks the Journal: http://lumentea.test/robots.txt**
`Disallow: /blog/` stops crawlers from fetching http://lumentea.test/blog/ and http://lumentea.test/blog/how-to-brew-green-tea/, the site's main informational content. Both URLs are still in the sitemap. Blocked URLs can be indexed without a snippet or not at all, and the internal links in them (for example to /teas/bai-mudan/) pass no value.
Fix: remove the Disallow line.

**4. Wrong canonical on the category page: http://lumentea.test/teas/**
`<link rel="canonical" href="http://lumentea.test/">` tells search engines that /teas/ is a duplicate of the homepage, so the "all teas" page will probably not be indexed. Its own og:url is /teas/, which contradicts the canonical.
Fix: make the canonical `http://lumentea.test/teas/`.

**5. Missing `<title>`: http://lumentea.test/blog/how-to-brew-green-tea/**
The page has no `<title>` element (only og:title), so search engines must generate a title.
Fix: add `<title>How to Brew Green Tea Without the Bitterness | Lumen Tea</title>`.

**6. Duplicate title: http://lumentea.test/guides/storing-tea/**
The title and og:title are "Lumen Tea | Small-Batch Loose Leaf Tea from Fujian", the same as the homepage. They do not describe the page, whose H1 is "How to store loose leaf tea", and they compete with the homepage.
Fix: use something like "How to Store Loose Leaf Tea | Lumen Tea".

### Medium

**7. Orphan page: http://lumentea.test/guides/storing-tea/**
No page links to it (not the nav, footer, Journal, or product pages). It can only be found through the sitemap, so it gets no internal link equity. It is also the only page under /guides/ while all other articles live under /blog/.
Fix: link to it from the Journal index and the product pages ("how to store it"). Consider moving it under /blog/ with a 301.

**8. Invalid Product JSON-LD: http://lumentea.test/teas/jasmine-silver-needle/**
The JSON-LD has trailing commas (`"availability": "https://schema.org/InStock",}` and `},\n}`). JSON parsers reject it, so the Product, price and stock data is ignored and the page cannot get product rich results.
Fix: remove the trailing commas and validate the markup.

**9. 404 URL in the sitemap: http://lumentea.test/teas/white-peony/**
The sitemap lists /teas/white-peony/, which returns 404. White Peony is Bai Mudan, so this looks like an old product URL that was renamed without a redirect.
Fix: remove it from the sitemap and 301-redirect /teas/white-peony/ to /teas/bai-mudan/ in case it has old links or traffic.

**10. Sitemap lists URLs that cannot be indexed: http://lumentea.test/sitemap.xml**
The sitemap includes /teas/jasmine-silver-needle/ (meta noindex), /teas/bai-mudan/ (X-Robots-Tag noindex), /blog/ and /blog/how-to-brew-green-tea/ (blocked by robots.txt), and /teas/ (canonicalised to another URL). A sitemap should list only 200, indexable, canonical URLs. Fixing #1–#4 and #9 resolves this.

**11. Redirect chain in the main navigation: http://lumentea.test/shop/ (linked from every page)**
The "Shop" link in the header of every page points to /shop/, which 301s to /store/, which 301s to /teas/. That is two hops on the most important sitewide link.
Fix: link directly to `/teas/`, and make /shop/ and /store/ each redirect to /teas/ in one hop.

**12. Broken internal link: http://lumentea.test/blog/how-to-brew-green-tea/**
The link "see Dragon Well" points to http://lumentea.test/teas/dragon-well/, which returns 404 (the page says the tea is not stocked yet).
Fix: remove the link until the product exists.

**13. Broken hreflang: http://lumentea.test/**
`<link rel="alternate" hreflang="zh-CN" href="http://lumentea.test/zh/">` points to a 404. There is also no self-referencing `hreflang="en"` (or en-GB) and no `x-default`, and the annotation exists on only one page, so the alternate could not return the link anyway.
Fix: remove it until a Chinese version exists, or add complete, reciprocal hreflang sets on every page.

**14. Duplicate meta description: http://lumentea.test/blog/**
The meta description and og:description ("Browse every loose leaf tea we sell: white and jasmine teas…") are copied from /teas/ and do not describe the Journal.
Fix: write a unique description about brewing guides and farm notes.

**15. Missing viewport meta: http://lumentea.test/blog/**
This is the only page without `<meta name="viewport" content="width=device-width, initial-scale=1">`. It will render at desktop width on phones, which hurts mobile usability under mobile-first indexing.
Fix: add the viewport tag.

**16. Missing H1: http://lumentea.test/contact/**
The page starts with `<h2>Get in touch</h2>` and has no H1.
Fix: change the first heading to an H1, for example "Contact Lumen Tea".

**17. Product image has no alt text: http://lumentea.test/teas/jasmine-silver-needle/**
`<img src="/img/jasmine.png" width="800" height="800">` has no alt attribute. Every other content image has descriptive alt text.
Fix: add something like `alt="Jasmine Silver Needle white tea buds"`.

### Low

**18. Title doesn't match the products: http://lumentea.test/teas/**
The title "All Teas | White, Green and Jasmine Tea | Lumen Tea" mentions green tea, but the page lists only two white teas. This can mislead searchers and raise bounce rate.

**19. Placeholder lastmod values: http://lumentea.test/sitemap.xml**
All 10 entries have `<lastmod>2026-10-01</lastmod>`, including a post published 2026-09-12 and a URL that is a 404. Identical lastmods look auto-filled and search engines tend to ignore them. Emit real modification dates.

**20. Duplicate homepage URL: http://lumentea.test/index.html**
It returns 200 with the homepage content. The canonical points to `/`, which reduces the damage. A 301 from /index.html to / is cleaner.

**21. Pages without structured data**
http://lumentea.test/teas/ (could use ItemList), http://lumentea.test/blog/ (Blog), http://lumentea.test/contact/ (ContactPage, or LocalBusiness/Store with address, phone and the Saturday collection hours), and http://lumentea.test/guides/storing-tea/ (Article). No page has BreadcrumbList markup or visible breadcrumbs.

**22. Incomplete BlogPosting: http://lumentea.test/blog/how-to-brew-green-tea/**
It is missing `dateModified`, `publisher` (Organization with logo), `description` and `mainEntityOfPage`. Adding them improves eligibility for article features.

**23. Incomplete Product schema: http://lumentea.test/teas/jasmine-silver-needle/, http://lumentea.test/teas/bai-mudan/**
No `brand`. The offers have no `itemCondition`, `priceValidUntil`, `shippingDetails` or `hasMerchantReturnPolicy`, although the site states free UK shipping over £30 and 30-day refunds. These are recommended for merchant listing results.

**24. /favicon.ico returns 404: http://lumentea.test/favicon.ico**
Pages declare `<link rel="icon" href="/img/icon.png">`, so browsers are covered. Some crawlers and tools still request /favicon.ico directly. The icon is also only 64×64; search results favicons should be at least 48×48 and ideally a multiple of 48 (for example 96 or 192).

**25. Server performance headers: site-wide**
The server answers with HTTP/1.0 (Python SimpleHTTP), ignores `Accept-Encoding: gzip` and sends no `Cache-Control` or `ETag`. The pages are small, so the impact is minor today, but production hosting should use HTTP/2 or HTTP/3, compression and caching headers.

**26. Content–product mismatch: http://lumentea.test/blog/how-to-brew-green-tea/**
The only Journal article targets "how to brew green tea", but the shop sells only white teas. Traffic from that query has no matching product. Consider a white-tea brewing guide, or retitle this one to cover green and white tea, since the article already says the temperatures apply to both.

## Checked and found OK
- All pages except the blog post have a unique `<title>`, and all have a meta description. Apart from #6 and #14 there are no duplicates.
- Canonicals are self-referencing on every page except /teas/.
- URLs without a trailing slash (/about, /teas, /blog) 301 to the slash version in one hop.
- Unknown URLs return a real 404 with `noindex` (no soft 404s).
- `lang="en"`, charset and Open Graph/Twitter tags are present on every page.
- Every `<img>` has width and height that match the real image size, so there is no layout shift.
- Organization and WebSite JSON-LD on the homepage is valid.
- Heading hierarchy is sensible everywhere except /contact/.
