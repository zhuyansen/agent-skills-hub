Tool: guard-skills — `clean-code-guard` (review mode, `references/review-checklist.md`).

### Summary
Do not merge. The retry loop never advances, so a persistent gateway failure hangs forever, and an exhausted retry would still mark the order paid.
Counts: 2 critical, 1 important, 0 nits

### Critical findings
- **Critical** — `shop/payments.py:30-36` — correctness / infinite loop (AI failure mode 13, plausible-but-wrong code): `attempt` is set to 1 and never incremented, so `while attempt <= MAX_ATTEMPTS` loops forever whenever `capture` keeps raising `PaymentError` (e.g. gateway down), logging "attempt 1" each time. Fix: `for attempt in range(1, MAX_ATTEMPTS + 1):` (or `attempt += 1` in the `except` branch).

Fix: after the final failed attempt re-raise the `PaymentError` (e.g. `for … else: raise`) so the status update only runs after a successful capture.

### Important findings
- **Important** — `shop/payments.py:29` — missing tests: no test for retry behavior (succeeds after 1–2 failures; raises and leaves order unpaid after 3). `Gateway.fail` already supports this. Fix: add those tests.
